# 逐项目分析模板

对 `sources/` 下每个项目产出一份 `docs/analysis/<name>.md`，固定六节：

## 1. 问题与约束
它在什么设备/权限/Android 版本约束下做取舍？作者明确说了哪些"不做"？

## 2. 运行模型
- 引擎：proot / proroot / chroot / 内嵌快照 / VM
- 根文件系统：放哪、什么格式、怎么解压/校验
- 命名空间：unshare 了哪些（mnt/pid/net/user），本机可不可用
- 权限：最终 UID、groups、capabilities、SELinux 域（能确认的写，不能确认的标注"未验证"）

## 3. 生命周期
- 启动：谁触发（service.sh / activity / 手动），是否阻塞开机
- 就绪判定：等什么条件（/data/media/0、用户解锁、端口监听）
- 监督：watchdog/重启策略/退出屏障
- 停止：怎么停、怎么保证子进程不泄漏

## 4. 数据与更新
- 配置/会话/日志/缓存位置
- 升级路径与回滚，坏版本怎么退
- 备份与迁移

## 5. 为什么这样写（要证据）
引用源码行号、issue、README/文档。**找不到证据就写"推测"，不要编。**

## 6. 更优雅的做法
逐条给出：能不能删依赖、能不能少一个脚本、能不能用现成轮子、能不能更可移植。
每条标注"代价/风险"。
