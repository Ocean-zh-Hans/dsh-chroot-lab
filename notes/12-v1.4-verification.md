## 0. 事故关联（2026-10-26）

本次验证中执行过：

```sh
mount --bind /sys/fs/selinux /data/local/tmp/selro
mount -o remount,ro,bind /data/local/tmp/selro
```

命令返回 0，但随后出现 zygote `selinux_android_setcontext(...) failed`、app native crash、system_server 重启崩溃。**这是本次系统崩溃的高度怀疑根因**；详见 `13-incident-2026-10-26-selinux-remount.md`。  
结论：**永远不要对 selinuxfs 做 bind/remount,ro**；需要遮罩时用 private ns 的 tmpfs + hardguard。

## 1. SELinux / SukiSU 隐藏特性

```sh
su -c 'getenforce; id; cat /proc/self/attr/current'
# Disabled
# uid=0(root) gid=0(root) groups=0(root) context=u:r:ksu:s0
# u:r:ksu:s0

su -c 'cat /sys/fs/selinux/enforce'
# 1

/system/bin/getenforce        # app
# Disabled
cat /sys/fs/selinux/enforce  # app
# Permission denied

su -c '/data/adb/ksud feature list'
# su_compat        ENABLED
# kernel_umount    ENABLED
# selinux_hide     ENABLED  "sanitize /sys/fs/selinux access results for app UIDs"
# mount_hide       ENABLED  "filter module mounts from /proc mount views of isolated and app processes"
# avc_spoof        ENABLED  "fix SELinux context leaks in AVC denial logs"
# sulog / adb_root DISABLED
```

**结论**
- 内核实际是 **Enforcing**（`enforce=1`）；但 `/system/bin/getenforce` 返回 `Disabled`，**不能用 `getenforce` 判断**；doctor 要读 `/sys/fs/selinux/enforce`。
- 普通 App 读 `enforce` 被 `EACCES`；`selinux_hide` 源码对 UID≥10000 返回 fake status page（`my_sel_open_handle_status`），所以“permissive 一定被普通 App 看见”不成立；但 permissive 仍是全局安全降级，root/特权扫描器可见，不能当隐藏手段。
- `selinux_hide`/`mount_hide`/`avc_spoof` 已启用；不要关。

来源：
- <https://github.com/tiann/KernelSU/blob/main/kernel/feature/selinux_hide.c>
- <https://github.com/tiann/KernelSU/pull/3457>
- PIF Detector README（untrusted_app 对 `/sys/fs/selinux/enforce` neverallow；引擎无 SELinux check）：<https://raw.githubusercontent.com/IR0NBYTE/playIntegrityFixDetector/refs/heads/main/README.md>

## 2. namespace

```sh
zcat /proc/config.gz | grep -E 'CONFIG_(UTS_NS|IPC_NS|PID_NS|USER_NS|NET_NS)'
# CONFIG_UTS_NS=y
# CONFIG_NET_NS=y
# CONFIG_PID_NS is not set
# CONFIG_USER_NS is not set
# （没有 CONFIG_IPC_NS）

busybox unshare --uts true          # rc=0
busybox unshare --ipc true          # unshare(0x8000000): Invalid argument
busybox unshare --mount --propagation private -m true  # rc=0
```

**结论**：UTS 可用，**IPC_NS 未编译**，v1.4 的 `--uts --ipc` 必须改成 `--uts`；只保留 mount+UTS。

## 4. debugfs / tracefs

```sh
su -c 'mkdir -p /data/local/tmp/dbgtest; mount -t debugfs debugfs /data/local/tmp/dbgtest; echo rc=$?'
# rc=0
su -c 'mkdir -p /data/local/tmp/trtest; mount -t tracefs tracefs /data/local/tmp/trtest; echo rc=$?'
# rc=0
grep ' /sys/kernel/tracing ' /proc/self/mountinfo
# 已挂载（tracefs）
grep ' /sys/kernel/debug ' /proc/self/mountinfo
# 默认未挂载；可手动 mount debugfs
```

**结论**：debugfs/tracefs 可挂；v1.4 的“debugfs/tracefs”成立；但 `/sys/kernel/debug` 默认未挂，启动时要显式 mount。

## 6. overlay / system-rw

### 6.1 直接放 `/data`（f2fs）→ 失败

```sh
mount -t overlay overlay \
  -o lowerdir=/system,upperdir=/data/local/tmp/ovl/upper,workdir=/data/local/tmp/ovl/work \
  /data/local/tmp/ovl/merged
# mount: Invalid argument
dmesg:
# overlay: case-insensitive capable filesystem on /data/local/tmp/ovl/upper not supported
# overlay: case-insensitive capable filesystem on /data/local/tmp/ovl2/lower not supported
```

### 6.2 upper/work 放 ext4 镜像 → 成功

```sh
# 64MB ext4 image on /data/media/0, mke2fs -b 4096
# util-linux losetup --sector-size 4096 --direct-io=off
mount -t ext4 /dev/block/loop46 /data/local/tmp/ovlext
mkdir -p /data/local/tmp/ovlext/upper /data/local/tmp/ovlext/work
mount -t overlay overlay \
  -o lowerdir=/system,upperdir=/data/local/tmp/ovlext/upper,workdir=/data/local/tmp/ovlext/work \
  /data/local/tmp/ovlmerge
# rc=0；ls 可见 system 内容；touch __ovl_test rc=0
```

**结论**：`system-rw` 的 upper/work **必须放 ext4**（rootfs 镜像内），不能放 f2fs `/data`；v1.4 已改。overlay 只用于私有 namespace 的 `/system`，不要挂到宿主。

## 7. losetup / mke2fs / e2fsck

```sh
/system/bin/losetup --help
# Toybox: -S SIZE = sizelimit，不是 sector-size；不支持 --sector-size
/data/data/com.termux/files/usr/glibc/bin/losetup --version
# util-linux 2.42.1（可用于 --sector-size 4096 --direct-io=off）
/system/bin/mke2fs --help  # 可用，支持 -b/-d
/system/bin/e2fsck --help  # 可用
/system/bin/resize2fs --help  # 可用
```

**结论**：lab/full 镜像工具链不能只用 Android toybox `losetup`；模块要自带 util-linux `losetup` 或明确依赖 Termux 的 util-linux。

## 8. 工作区/镜像目录权限

```sh
mkdir -p /data/media/0/.dsh; chmod 700 /data/media/0/.dsh; touch .nomedia
ls -ld /data/media/0/.dsh   # drwx------ root media_rw
# Termux app:
ls -ld /sdcard/.dsh         # drwx------ root media_rw
ls /sdcard/.dsh             # Permission denied
```

**结论**：0700 + `.nomedia` 对普通 App 隐藏有效；root 域可访问。`/sdcard/DSH` 工作区另设 2777/0666。

## 10. 本次纠正清单

| 之前写法 | 实测/来源 | 改正 |
|---|---|---|
| `unshare --uts --ipc` | `IPC_NS` 未编译，`--ipc` EINVAL | 只 `--uts` |
| `uiautomator dump` 可用 | rc=137 Killed，无文件 | 只承诺 `runtest`；input+screencap 兜底 |
| `system-rw` upper 放 `/data/adb/chroot/overlays` | f2fs case-insensitive，overlay EINVAL | 放 ext4 rootfs `/var/lib/dsh/overlays` |
| `/system/bin/losetup` 可用 `--sector-size` | toybox `-S` 是 sizelimit | 自带 util-linux losetup |
| permissive 一定被 App 检测 | untrusted_app 读 enforce EACCES；`selinux_hide` fake status | 改成“不保证可见，但全局安全降级” |
| `getenforce` 判断 SELinux | 本机返回 Disabled，实际 enforce=1 | doctor 读 `/sys/fs/selinux/enforce` |
| `/sys/kernel/debug` 默认可用 | 默认未挂载 | 启动时显式 mount debugfs |
